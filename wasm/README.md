# WASM

`build-headless.sh` builds the headless vpinball engine (`vpinball-headless`)
from the pinned `external/vpinball` submodule plus the patch series in
`modules/headless/patches/`, around the vpx-js bridge
(`modules/headless/bridge/vpx_wasm_bridge.cpp`, the `VpxWasm_*` C ABI), and
deploys it to `demo-browser/public/wasm/`.
That directory is a committed release build — CI never rebuilds it, it
verifies `build-info.json` provenance instead (`npm run
verify:engine-manifest`) and boots the engine on a static host
(`test/harness/verify-pages.mjs --dist=demo-browser/dist` in pages.yml). So
after changing the submodule pin, a patch or the bridge, rebuild locally and
commit the binaries together with the code change, from a clean tree — the
build applies every on-disk patch, the manifest is generated by the build
(never edit it by hand; `engine-inputs.mjs` lists what it hashes), and the
verifier refuses manifests built with uncommitted inputs. The TypeScript side
of the bridge is `lib/wasm/`.

The engine is committed rather than fetched (no LFS — Pages cannot serve it —
no Release assets, no per-push rebuild) so Pages deploys and
`verify:engine-manifest` need no auth, toolchain, or submodule checkout.
The build targets `-DARCH=wasm32`, which pins `external/vpinball` to
`64a480a9`: upstream moved its web build to wasm64 (memory64) and dropped the
wasm32 toolchain right after (`f4a28d2d`), so following upstream master means
porting the bridge and `lib/wasm` to 64-bit pointers first.

The engine uses pthreads, so its page must be cross-origin isolated: a server
you control sends `Cross-Origin-Opener-Policy: same-origin` and
`Cross-Origin-Embedder-Policy: require-corp` (as the vite dev server does);
static hosts that cannot send headers (GitHub Pages) build the demo with
`VITE_COI_SW=1`, which ships a service worker that adds them
(`demo-browser/coi-sw.js`).

```bash
npm run build:wasm:headless          # release
npm run build:wasm:headless:debug    # -O0, assertions
```

Needs emsdk 6.0.13 (`$EMSDK`, `~/projects/emsdk`, `/tmp/emsdk-6.0.13`, or
`emcc` on `PATH`) and bash ≥ 4 (`mapfile`). The first run builds the
third-party wasm libraries (`external.sh`, one-time).

## Patches

Never hand-edit `external/vpinball`. The series is kept as small as upstream
allows; everything vpx-js specific lives in the bridge, which reads engine
state through upstream's public API (script getters, the display resolver,
part data):

- `0001-headless-player` — `ENABLE_HEADLESS` builds run the player without
  rendering (Noop backend, no render thread or swap chain, no textures, no
  display) and step it from the host (`Player::StepHeadlessFrame`).
- `0002-player-state-accessors` — `Primitive::GetCurrentFrame`,
  `DispReel::GetReelValue`, `Player::m_lastScriptError`.
- `0003-vpx-js-headless-target` — the `vpinball-headless` CMake target around
  the bridge (`-DVPX_HEADLESS_BRIDGE=<source>`). Local only.

0001 and 0002 are written for upstream (one PR each); 0003 stays here. The
numbered file names are the series order, and the files are byte exact
(`.gitattributes`: CRLF upstream sources stay CRLF). The build applies the
series to a throwaway worktree, compares contents, and classifies the
submodule as `pristine` (apply), `applied` (skip) or `broken` (refuse). To
change a patch, reset the submodule (`git -C external/vpinball reset --hard &&
git -C external/vpinball clean -fd`), apply the series as commits, edit, and
regenerate the files with `git format-patch`.
